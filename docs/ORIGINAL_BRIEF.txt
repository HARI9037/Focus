You are a senior cross-platform software architect, Flutter engineer, Android systems engineer, Windows application engineer, product designer, database architect, security engineer, and QA engineer.
Your task is to DESIGN AND BUILD a production-quality personal productivity application named:
FOCUS
============================================================
1. PRODUCT VISION
============================================================
Focus is a private, local-first, cross-platform personal productivity and digital-discipline application for:
1. Android
2. Windows
The application exists because the user currently spends too much time on their phone throughout the day, starting soon after waking and continuing until going to sleep.
Focus should not merely display screen-time statistics.
It should actively help the user:
- control when the phone can be used;
- reduce unnecessary smartphone usage;
- enforce healthy digital boundaries;
- manage tasks and projects;
- plan each day;
- enter distraction-free focus sessions;
- capture notes and ideas;
- track goals and habits;
- understand behavioral patterns;
- analyze phone usage;
- measure productivity;
- correlate digital behavior with productivity;
- produce actionable daily/weekly/monthly reports;
- synchronize useful productivity information between Android and Windows.
The product philosophy is:
"Control the environment. Protect attention. Understand behavior. Focus on what matters."
Focus should feel like a premium personal productivity operating layer rather than a generic to-do application.
============================================================
2. CRITICAL PRODUCT PRINCIPLES
============================================================
Follow these principles throughout the implementation.
1. LOCAL-FIRST
Personal behavioral data should primarily remain on the user's devices.
Do not require cloud connectivity for basic functionality.
Tasks, notes, projects, habits, usage history, Focus sessions and analytics should remain functional offline.
2. PRIVACY-FIRST
Phone usage data is sensitive.
Do not unnecessarily transmit raw behavioral information to third-party services.
Design the architecture so AI functionality can later receive aggregated/sanitized information instead of unrestricted raw data.
3. PRODUCTIVITY WITHOUT AI
The core application MUST work without an LLM.
AI is an optional intelligence layer, not the foundation of the application.
4. CROSS-PLATFORM
Use Flutter as the primary application framework unless an unavoidable technical requirement requires platform-specific implementation.
Target:
- Android
- Windows
Use native Android Kotlin code/platform channels where Flutter alone cannot provide required operating-system capabilities.
5. MODULAR ARCHITECTURE
Do not create one giant application.
Use clearly separated domains/modules.
6. SAFETY
Never make emergency communication inaccessible.
Night Lock must always provide a safe emergency escape mechanism.
7. NO FAKE CAPABILITIES
Do not claim Android APIs can perform operations that Android does not permit.
If a capability requires:
- Usage Access
- Accessibility Service
- Notification Listener
- Device Owner
- foreground service
- overlay permission
- battery optimization exemption
- native Android APIs
implement the correct permission architecture and clearly document the limitation.
Do NOT pretend a normal Android application can physically shut the device down and automatically boot it later.

3. PRIMARY FEATURE — NIGHT LOCK
============================================================
Night Lock is one of the defining features of Focus.
DEFAULT SCHEDULE:
Phone available:
07:00 AM → 09:00 PM
Night Lock:
09:00 PM → 07:00 AM
The schedule must eventually be configurable.
At 09:00 PM, Focus automatically enters Night Lock.
At 07:00 AM, Focus automatically exits Night Lock.
Night Lock does NOT mean physically powering the phone off.
It means creating the strongest reliable software-level restricted-device experience that can reasonably be implemented on Android.
